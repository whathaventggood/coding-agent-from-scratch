# 从零实现 Coding Agent

这是一个用于学习 Python 工程与 Agent 原理的 Coding Agent 项目。

## 当前功能

- 解析 JSON 工具请求
- 读取文本文件
- 分页列出目录当前一层的文件和子目录，并标明类型，支持模型逐层探索大工作区
- 根据名称分发工具
- 返回结构化错误信息
- 在单个文本文件中搜索关键词并返回匹配行号
- 将无效 UTF-8 文件转换为清晰的错误结果
- 精确替换文件中的唯一文本，零匹配或多匹配时拒绝写入
- 支持用空字符串删除指定文本
- 使用模拟模型响应演练工具调用与最终回答循环，并限制最大执行步数
- 接入 DeepSeek，实现真实的 read_file 工具调用、结果回传和最大步数限制
- 将模型生成的无效 JSON 参数转换为工具错误并回传
- 在本地指定受信工作区后，允许 DeepSeek 调用本地预选的 pytest 或 unittest 验证方案；工作目录越界会被拒绝
- 在受信工作区内向模型开放单文件关键词搜索；仅在本地调用方明确开启 `allow_edit=True` 时开放精确编辑
- 工作区内的文件工具相对路径从工作区根目录解析，越界路径被拒绝
- 真实 DeepSeek 请求和本地工具执行共用一个 Agent Loop，并保留工具调用 ID
- 在显式开启编辑权限后创建工作区内的新文本文件，并拒绝覆盖已有文件
- 在显式开启编辑权限后创建工作区内的新目录，不递归创建缺失父目录
- 在显式开启编辑权限后安全重命名工作区内的普通文件，拒绝覆盖已有目标或自动创建父目录
- 在工作区内递归搜索文本关键词，跳过常见环境目录、符号链接和非 UTF-8 文件，并限制结果数量
- 只读检查 Git 状态、未暂存差异和已暂存差异，帮助模型在结束前审阅实际改动
- 在 pytest 验证方案下支持模型只运行指定测试文件；CLI 收尾始终使用本地预选方案执行完整独立复验
- 在显式开启编辑权限后删除工作区内的普通文件，拒绝删除目录或符号链接
- 汇总多份 JSON 运行记录，统计成功率、独立复验、工具调用和文件变化

## 安装与运行

```bash
python -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/coding-agent --help
```

安装后可在其他目录使用 `.venv/bin/coding-agent`、
`.venv/bin/coding-agent-evaluate` 和 `.venv/bin/coding-agent-benchmark`。
开发环境使用 `.venv/bin/python -m pip install -r requirements-dev.txt`，
依赖版本统一定义在 `pyproject.toml`。Python 需要 3.11 或更新版本。
GitHub Actions 在 Python 3.11 和 3.14 上安装项目、运行离线测试并检查三个命令入口；
这些检查不需要 `DEEPSEEK_API_KEY`，也不会发出真实模型请求。

## 配置 DeepSeek

运行前设置环境变量：

```bash
export DEEPSEEK_API_KEY="你的密钥"
```

不要把真实 API Key 写入代码或提交到 Git。

## 命令行使用

对受信工作区运行任务：

```bash
.venv/bin/python cli.py --workspace . "请读取 demo.txt 并告诉我内容"
```

对受信 Git 仓库执行修复任务时，添加 `--allow-edit`；完成后 CLI 会独立运行一次固定的
pytest，并显示相对任务开始基线的文件级变化。复验失败时进程以非零状态结束：

```bash
.venv/bin/python cli.py --workspace /你的/受信仓库 --allow-edit "修复失败的测试并复测"
```

对 Git 工作区的编辑任务，可显式开启失败恢复：

```bash
.venv/bin/python cli.py \
  --workspace /你的/受信仓库 \
  --allow-edit \
  --rollback-on-failure \
  "修复失败的测试并复测"
```

当模型执行异常或 CLI 独立复验失败时，该开关会将本次任务修改、
删除或新建的 Git 可见普通文件恢复到任务开始时状态，包括保留运行前
已存在的未提交改动。终端和 JSON 报告仍保留 Agent 原本尝试产生的变化，
并另行记录恢复/移除路径及回滚错误。

该功能仅承诺 Git 可见普通文件；被 `.gitignore` 忽略的文件、空目录、
符号链接、Git 子模块内部变化和任务期间其他程序的并发修改不在安全回滚保证内。
受影响的符号链接或无法读写的路径会让回滚显式失败，不会被当作恢复成功。

完整验证默认使用 pytest。对于基于 Python 标准库 `unittest` 的项目，
由本地调用者显式选择验证方案：

```bash
.venv/bin/python cli.py \
  --workspace /你的/受信仓库 \
  --allow-edit \
  --verification-profile unittest \
  "修复失败的测试并复测"
```

当前只允许 pytest 和 unittest 两个固定 profile。profile 由本地 CLI
或受控 benchmark 清单选择，模型工具参数中没有命令、profile 或额外参数。
底层始终使用固定参数列表和 shell=False，不会执行任务文本或模型生成的
shell 命令。pytest 专属的单文件测试工具只在 pytest profile 下开放。
CLI 的最终独立复验使用与 Agent 相同的 profile，JSON 运行报告会记录
verification_profile。benchmark 任务也可通过同名字段显式选择方案。


可通过 `--report-json` 将同一次运行的任务、最终状态、模型回答、工具轨迹、
独立复验和文件变化保存为 UTF-8 JSON。报告文件的父目录必须已经存在，
目标文件必须不存在，CLI 不会覆盖已有报告：

```bash
.venv/bin/python cli.py \
  --workspace . \
  --allow-edit \
  --report-json /tmp/coding-agent-run-001.json \
  "修复失败的测试"
```

多次运行后，可把一个或多个 JSON 记录交给评测汇总入口：

```bash
.venv/bin/python evaluate_reports.py \
  /tmp/run-001.json \
  /tmp/run-002.json
```

汇总结果包括运行成功率、独立复验状态、工具调用及错误数量、文件变化总数，
以及模型请求数、完整消息最大峰值、历史裁剪次数、删除消息数和释放字符数，
并列出每次运行的简要结果。没有 `context_usage` 的旧 JSON 仍可读取，但会
明确显示上下文指标不可用。该入口只读取已有记录，不会再次请求模型。

## 运行固定任务集评测

配置 `DEEPSEEK_API_KEY` 后，可以自动在临时 Git 工作区中依次运行固定任务，
保存每个任务的 JSON 报告，并生成汇总结果：

```bash
.venv/bin/python run_benchmark.py \
  benchmark_tasks.json \
  --output-dir /tmp/coding-agent-benchmark-001
```

--output-dir 必须指向一个尚不存在的目录，避免覆盖以前的评测结果。
每个任务使用独立的临时工作区，任务结束后自动清理；逐任务报告和
summary.json 会保留在输出目录中。该命令会产生真实模型 API 请求。

### 当前基准记录

完整的[演示与量化记录](docs/benchmark-report.md)说明了历史数据来源、样本量限制、可复现步骤和下一轮量化口径。

在相同的两个固定任务、相同模型和每任务最多 8 次模型请求的条件下：

| 版本       | 成功任务 | 独立复验通过 | 模型请求 | 工具错误 | 最大消息峰值 |
|----------|-----:|-------:|-----:|-----:|-------:|
| 工作流指导前   |  1/2 |    1/2 |   13 |    2 |   3205 |
| 工作流指导 v1 |  2/2 |    2/2 |   13 |    1 |   4721 |

工作流指导要求模型避免在没有新证据时重复失败读取；当测试或导入依赖
缺失源文件且允许编辑时，优先使用 `create_file`，修改后必须运行测试。
第二次评测中，缺失文件任务依次完成了文件创建、定向测试、完整测试和
独立复验。

以上每个版本目前只运行一次，结果用于记录真实执行链和发现回归，
不代表统计稳定的成功率。模型输出具有非确定性，后续可通过重复运行扩大样本。

2026-09-24 在当前主线上按同一两任务清单连续复测 5 轮，观察到 8/10 次任务成功且独立复验通过；`fix-addition` 为 5/5，`create-text-normalizer` 为 3/5。两次失败均因 8 次模型请求额度耗尽。逐轮数据、失败阶段和样本限制见[演示与量化记录](docs/benchmark-report.md)，不要将 8/10 外推为总体成功率。

针对这两次失败，工作区任务提示现会向模型说明本次模型请求上限、要求给最终答复预留一次请求，并在测试已指向缺失源文件时减少重复探索、先确认接口再创建文件。该提示不改变工具权限、请求上限或 CLI 独立复验。同条件再跑 5 轮后，本样本观察到 10/10 成功且独立复验通过、57 次模型请求（旧组为 8/10、62 次）；工具错误则从 4 增至 5。完整数据与限制见[演示与量化记录](docs/benchmark-report.md)，这不是稳定成功率或因果改进的证明。

可用 `--max-steps 8` 调整模型请求次数。编辑任务开始前，CLI 会记录 Git
可见文件的内容基线；任务结束后只报告相对该基线新增、修改或删除的文件。运行前已有且本次未继续变化的改动不会被列为本次变化。非
Git 工作区仍可运行 Agent，但报告会明确说明无法进行 Git 基线归因。

当前报告只提供文件级变化，不判断每一行由谁修改；被 `.gitignore` 忽略的文件、Git 子模块内部变化、任务执行期间其他程序的并发修改，以及无法读取的文件不在可靠归因范围内。

运行报告还会按模型请求轮次展示结构化工具轨迹，包括工具名、成功或失败状态和精简结果摘要。文件读取与编辑不会在轨迹中直接打印完整文件内容；完整工具结果仍会按协议回传给模型。

DeepSeek 请求失败时，CLI 会把常见 SDK 异常转换成清晰的失败原因，包括 Key 鉴权失败、请求限流、请求超时、网络或代理连接失败，以及其他
HTTP 服务错误。失败前已经收集的工具轨迹和文件变化仍会进入最终报告，进程以非零状态退出。模型请求的单次超时时间为 30
秒，可重试错误最多自动重试一次。

Agent Loop 达到最大模型请求次数、收到不完整响应、遇到未知响应类型或模型请求未开放工具时，CLI 会保留已有工具轨迹和文件变化，报告明确失败原因，并以退出码
1 结束，不再把这些终止状态显示为成功。

为避免大文件或连续工具输出无限扩大模型消息历史，Agent 回传给模型的单次工具结果最多保留前 4000
个字符，并附加明确的截断标记。该限制只作用于模型消息，不会截断磁盘文件或修改工具的原始执行结果。

`read_file` 支持可选的 `start_line` 和 `max_lines` 参数，用于按行分段读取大文件。行号从 1 开始，单次最多读取 200
行；返回结果会说明本次读取范围和文件总行数。未提供这两个参数时仍保持原来的整文件读取行为。分段结果如果仍超过 4000
个字符，回传模型时依然会触发单次工具结果截断。

`list_files` 每次最多返回同一目录的一层 50 个条目，条目正文最多约 3000 字符。若还有后续条目，结果末尾会给出 `start_after` 游标；下一次保持 `path` 不变并传入该游标即可继续。小目录的原有输出不变。分页按文件名排序，但不是目录快照；如果其他进程在两次调用之间增删或重命名条目，可能出现跳过或重复，需重新列目录核对。

除单次工具结果限制外，尚未被模型看过并压缩的工具结果最多占用 12000
个原始字符。新工具结果至少完整提供给模型一次；下一次模型响应返回后，旧工具结果会替换为包含工具名、成功或失败状态及结果摘要的压缩内容，并释放对应预算。

同一模型响应中的多个工具结果尚未被模型看过，因此不能互相压缩；如果这一批结果耗尽预算，Agent
仍会在执行下一个工具前终止，避免产生无法回传结果的写入副作用。当前压缩只处理工具结果正文，assistant/user
消息和压缩摘要本身仍会继续增长，因此它还不是整个模型上下文的绝对 token 上限。

CLI 还会观测每次模型请求前的完整消息历史近似字符数，并在文本报告和
JSON 运行记录中展示模型请求次数、各次消息大小、峰值、旧工具消息压缩数
以及释放的工具结果原文字符数。该统计包含 user、assistant 和 tool
消息及其序列化结构，只用于稳定对比运行趋势，不等同于模型供应商计算的
精确 token 数，也不会主动裁剪完整消息历史。

12000 字符限制仍只约束尚未压缩的工具结果原文；即使这部分预算已经释放，
user 消息、assistant 工具调用、压缩摘要和 JSON 结构仍会计入完整消息历史
观测值。

当完整消息历史在下一次模型请求前超过 24000 个近似字符时，Agent
会保留最初的 user 任务和最新一轮尚未被模型看过的 assistant/tool
完整交互，并把更早、已经处理过的工具交互替换为最多 2000 字符的摘要。
运行报告会记录裁剪次数、被删除的旧消息数和释放的历史字符数。

如果初始任务与最新未读工具交互本身已经超过该阈值，Agent 会在下一次
模型请求前明确失败，不会为了满足阈值而删除模型尚未看过的工具结果。
该阈值仍是本地 JSON 序列化后的近似字符数，不是供应商的精确 token
上限。

## 运行 DeepSeek 读取示例

```bash
python deepseek_model.py
```

默认只开放 `read_file`；本地调用方指定受信工作区后，会额外开放目录探索、搜索、测试和 Git 检查等只读工具。`edit_file`、
`create_file`、`create_directory`、`rename_file` 和 `delete_file`
还需要调用方显式传入 `allow_edit=True`。

## 运行受控测试演示

仅在信任本仓库测试代码、并已配置 `DEEPSEEK_API_KEY` 时运行：

```bash
.venv/bin/python demo_run_tests.py
```

演示脚本把当前项目设为受信工作区，向模型开放 `read_file`、`list_files`、`search_file` 和 `run_tests`，不开放编辑。`run_tests`
只执行固定的 `python -m pytest -q`，模型不能通过工具参数改变工作区根目录。运行会产生真实 API 请求；路径检查和 `shell=False`
不构成恶意代码沙箱。

## 运行临时工作区修复演示

已配置 `DEEPSEEK_API_KEY` 后运行：

```bash
.venv/bin/python demo_fix.py
```

脚本创建临时工作区，放入一个故意写错的加法函数和一条测试。它先确认测试失败，再让模型根据失败信息检查、修复和复测；模型回答后，脚本会独立重跑测试。临时工作区在脚本结束后自动清理。运行会产生真实
API 请求。这里的路径限制和固定命令仍不是恶意代码沙箱，只应使用受信的演示内容。
